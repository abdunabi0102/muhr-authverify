# Authenticated verification for deep image watermarks: code and results

Code, Kaggle notebooks and result tables for the manuscript
The repository contains:
- the keyed codec: truncated HMAC tag, SIV-style AES-CTR, keyed permutation, keyed whitening and BCH;
- a vectorised BCH decoder;
- the experiment scripts and offline analysis scripts;
- the Kaggle notebooks that produced every result in the paper;
- the analysed result tables (CSV).

## What is not included, and why

| Item | Reason |
|---|---|
| Master keys and per-experiment keys (`*.key`) | Security. Every experiment used a fresh key, and keys are not released. Results that need a key (verification rates) are given as analysed CSVs. |
| Host-network weights (`best.pt`) | The primary threat model assumes a secret decoder (setting S1). Weights are available from the authors on reasonable request for research use. |
| Raw decoder outputs (`chunk_*.npz`) | These files are stored next to the experiment keys. Available on request. |
| COCO 2017 and DIV2K images | Third-party datasets with their own licences. Image indices are listed below. |

## Layout

```
code/
  muhr/            host network (U-Net encoder, STN decoder), dissertation codec, data and attacks
  muhr_exp/        codec v2 (designs A, C, E, F, G8, G9; whitening), FastBCH, statistics,
                   baseline wrappers, regeneration attacks
  scripts/         experiment drivers (e3_marked, e4_unmarked, e2_baselines, e8_games, examples,
                   train_image) and offline analysis (analyze_marked, analyze_fa, analyze_baselines,
                   analyze_e8)
notebooks/         Kaggle drivers (comments in Uzbek); choose the stage with STAGE = "..."
results/           analysed CSVs, one folder per experiment; results/flat/ holds the tables
                   used directly by the figure scripts
figures/           scripts for Figs. 1-8 (out/ is created on first run)
```

## Requirements

Python ≥ 3.10 and PyTorch ≥ 2.1 (install for your CUDA version from pytorch.org), then:

```
pip install -r requirements.txt
```

The baselines are loaded through the public Video Seal code base at commit `f12875a9b5e711e0c6e2dc3a22aca18231ce4a1a` (https://github.com/facebookresearch/videoseal). The notebooks clone and pin it.

## Reproducing the paper

All GPU runs used a Kaggle Tesla T4. The decoder is keyless, so the GPU stages store decoder outputs once. Every keyed decision is then computed on CPU by the `analyze_*` scripts.

| Paper item | Notebook and stage | Analysis script | Result folder |
|---|---|---|---|
| Table III, Fig. 4 (false acceptance, tag truncation) | `Muhr_Exp_Kaggle`, `e4_unmarked` | `analyze_fa.py` | `results/e4_false_acceptance/` |
| Table IV, Fig. 5 (calibration of baselines) | `Muhr_Baselines_Kaggle`, `bl_unmarked` | `analyze_baselines.py --unmarked` | `results/e4c_baselines_unmarked/` |
| Table V (verification and quality, COCO) | `Muhr_Exp_Kaggle`, `e3_coco`; `Muhr_Baselines_Kaggle`, `bl_marked` | `analyze_marked.py`; `analyze_baselines.py --marked` | `results/e3_coco/`, `results/e2_baselines_marked/` |
| Table V (DIV2K column) | `Muhr_Exp_Kaggle`, `e3_div2k` | `analyze_marked.py` | `results/e3_div2k/` |
| Table VI, Fig. 8 (codec inside Pixel Seal and Video Seal) | `Muhr_Baselines_Kaggle`, `bl_codec` | `analyze_baselines.py --codec-marked` | `results/bl_codec/` |
| Fig. 6 (operating points) | none (offline) | `figures/fig_design.py` | `results/e3_coco/errors_best_hyp.csv` |
| Table VII (ablations) | `e6_stn_off`, `e3_coco_tiled`, plus offline analysis | `analyze_marked.py`, `analyze_fa.py` | `results/e6_stn_off/`, `results/e3_coco_first500/`, `results/e3_coco_tiled/` |
| Fig. 7 (example images) | `Muhr_E10_Examples_Kaggle` | `figures/fig_examples.py <e10 output dir>` | not released (derived from COCO images) |
| Table VIII (security games) | `Muhr_Exp_Kaggle`, `e8_games` | `analyze_e8.py` | `results/e8_games/` |
| Table IX (regeneration) | `Muhr_E9_Regen_Kaggle` | `analyze_marked.py`, `analyze_baselines.py` | `results/e9_regen/` |

Figs. 1 and 3 are drawn by `figures/svg_figs.py <outdir>` and rendered to PDF with `node figures/render.js <outdir> <outdir>` (needs Playwright).

## Data splits

- **T-COCO (marked tests):** COCO 2017 val images 1 500–3 499 in sorted file-name order. The host network was trained on train2017.
- **Unmarked tests:** the first 10 000 COCO 2017 test images in sorted order, plus 500 synthetic degenerate images generated by `e4_unmarked.py`.
- **DIV2K:** the first 500 high-resolution training images by file name, downscaled to a longest side of 1 024 px.

## Security note

This code is for research. A deployment must:
- generate its own master key and keep it secret;
- rotate keys per author or per period (see Proposition 3 in the paper);
- rate-limit the verifier;
- use privately trained network weights.
